# تصميم: إضافة قاعدة بيانات للكويز القبطي

> تاريخ: ٢٢ سبتمبر ٢٠٢٦ — مسودة للمراجعة قبل التنفيذ.

## ١. الهدف

تحويل الكويز من موقع ساكن بيشتغل على جهاز كل واحد لوحده، إلى نظام على النت بقاعدة بيانات، بحيث:

- الطالب يكتب اسمه ويحل، واسمه وإجاباته تتسجل.
- جورج (الأدمن) يضيف ويعدل الأسئلة من صفحة ويب بدل ما يعدل ملف كود.
- جورج يراجع كل المحاولات وكل إجابة فيها بالتفصيل.
- جورج يشوف إحصائية بأصعب الأسئلة على الناس.

## ٢. الوضع الحالي

| الحاجة | الوضع دلوقتي |
|---|---|
| التقنية | HTML + CSS + JavaScript عادي. مفيش `npm`، مفيش build، مفيش سيرفر. |
| الأسئلة | ١٠٠ سؤال مكتوبين بالإيد في `js/questions.js` — ١٦ سهل، ٣٨ متوسط، ٤٦ صعب. |
| الصعوبة | مش حقل جوه السؤال — بتتحدد بالمصفوفة اللي السؤال متحطوط فيها (`EASY_QUESTIONS` إلخ). |
| الامتحان | بيسحب ٤٠ سؤال عشوائي حسب `QUOTAS = { easy: 10, medium: 20, hard: 10 }` في `js/script.js`. |
| النتيجة | بتتحفظ في `localStorage` على جهاز الطالب. محدش غيره بيشوفها. |
| المدة | ١٥ دقيقة (`QUIZ_DURATION_SECONDS`). |
| اللغات | عربي / إنجليزي / فرنساوي، وثيم فاتح وغامق. |

## ٣. القرارات المتفق عليها

هي دي القرارات اللي اتاخدت في النقاش، ومكتوبة هنا عشان متترجعش فيها من غير قصد:

1. **الاستخدام:** كل طالب يحل من موبايله في أي وقت من لينك على النت.
2. **الأدمن:** جورج بس. حساب واحد. مفيش خدام تانيين ولا نظام موافقة على الأسئلة.
3. **بيانات الطالب:** الاسم بس. مفيش كنيسة ولا فصل ولا تليفون.
4. **المحاولات:** مفتوحة. الطالب يحل زي ما هو عايز، وكل محاولة تتسجل لوحدها بتاريخها.
5. **المراجعة للطالب:** أيوة، يشوف الإجابات الصح بعد ما يخلص زي دلوقتي. الهدف تعليمي مش امتحان رسمي.
6. **مكان الأسئلة:** كلها تنتقل للداتابيز، و`js/questions.js` يتشال بعد التأكد من النقل.
7. **التقنية:** Supabase (Postgres مستضافة + API متولد منها + نظام تسجيل دخول). مفيش سيرفر باك إند مكتوب بالإيد.

## ٤. البنية التقنية

```
متصفح الطالب / متصفح الأدمن
        │
        │  مكتبة supabase-js من CDN
        ▼
   Supabase
   ├── Postgres (الجداول)
   ├── API متولد تلقائي من الجداول
   ├── Auth (حساب الأدمن الواحد)
   └── Row Level Security (قواعد مين يقدر يشوف إيه)
```

الملفات الساكنة (HTML/CSS/JS) بترفع على Cloudflare Pages أو Netlify ببلاش، مربوطة بالـ git repo.

مفيش `npm` ولا build step. مكتبة Supabase بتتجاب من CDN بسطر `<script>` واحد، فالمشروع بيفضل بنفس بساطته الحالية.

## ٥. الجداول

### `questions`

```sql
create table questions (
  id          bigint primary key,
  type        text not null check (type in ('mcq', 'truefalse', 'fill')),
  difficulty  text not null check (difficulty in ('easy', 'medium', 'hard')),
  question    text not null,
  options     jsonb,
  answer      jsonb not null,
  lang        text,
  active      boolean not null default true,
  created_at  timestamptz not null default now()
);

create index on questions (difficulty) where active;
```

ملاحظات:

- **`id`** بنفس النظام الحالي بالظبط: `X_XXXX` حيث الرقم الأول هو النوع (`1` = أكمل، `2` = اختيار من متعدد، `3` = صح وغلط) والباقي ترقيم متسلسل لكل نوع لوحده. القيمة رقم عادي (`2_1001` قيمته `21001`). الصعوبة مش داخلة في الرقم عن قصد، عشان تقدر تنقل سؤال بين المستويات من غير ما ترقمه من أول.
- **`difficulty`** بقى عمود حقيقي بدل ما كان "المصفوفة اللي السؤال فيها". ده معناه إن نقل سؤال من متوسط لصعب بقى تغيير قيمة، مش نقل كود.
- **`options`** مصفوفة الاختيارات — لأسئلة `mcq` بس، و`null` لغيرها.
- **`answer`** بيقبل التلات أنواع في عمود واحد لأنه `jsonb`: رقم للـ `mcq` (يبدأ من صفر)، `true`/`false` للـ `truefalse`، ونص للـ `fill`.
- **`lang`** قيمتها `'cop'` لو نص السؤال كله قبطي، و`null` لغير كده — زي ما هي دلوقتي.
- **`active`** بتخلي إخفاء سؤال من الامتحان ممكن **من غير حذفه**. ده مهم: لو لقيت سؤال فيه غلط، بتخفيه فوراً وإجابات الناس القديمة عليه تفضل موجودة في السجل بدل ما تضيع.
- ترميز الخط القبطي `{{ ... }}` و `(( ... ))` بيتكتب جوه `question` و`options` زي ما هو مكتوب دلوقتي بالظبط. مفيش حاجة اتغيرت في ده.

**حساب الـ id الجاي:** صفحة الأدمن بتحسبه لوحدها قبل الإضافة، فجورج مش محتاج يعدّ بإيده:

```sql
-- prefix = 1 أو 2 أو 3 حسب النوع
select coalesce(max(id), prefix * 10000 + 1000) + 1
from questions where id / 10000 = prefix;
```

### `attempts`

```sql
create table attempts (
  id            uuid primary key,
  student_name  text not null check (length(trim(student_name)) between 1 and 60),
  started_at    timestamptz not null default now(),
  finished_at   timestamptz,
  score         integer,
  total         integer
);

create index on attempts (started_at desc);
```

سطر لكل محاولة. مفيش ربط بين المحاولات بنفس الاسم — لو "مينا" حل تلات مرات، بيبقى تلات سطور منفصلة، وده المطلوب.

`finished_at` و`score` و`total` بتفضل `null` لو الطالب قفل الصفحة في النص. المحاولات الناقصة دي بتفضل مسجلة وبتظهر في صفحة الأدمن معلّمة إنها ما خلصتش.

### `attempt_answers`

```sql
create table attempt_answers (
  id           bigserial primary key,
  attempt_id   uuid not null references attempts(id) on delete cascade,
  question_id  bigint not null references questions(id),
  position     integer not null,
  given_answer jsonb,
  is_correct   boolean not null,
  answered_at  timestamptz not null default now(),
  unique (attempt_id, question_id)
);

create index on attempt_answers (question_id);
```

سطر لكل سؤال في كل محاولة — يعني ٤٠ سطر للمحاولة الكاملة.

- **`position`** ترتيب السؤال في الامتحان بتاع الطالب ده (١ إلى ٤٠). الأسئلة بتتعرض عشوائي فالترتيب بيختلف من واحد للتاني، وده بيخلي شاشة المراجعة تعرض الامتحان بنفس ترتيبه الأصلي.
- **`given_answer`** إجابة الطالب. `null` لو ساب السؤال من غير إجابة.
- الإجابات بتتسجل **سؤال بسؤال وقت ما يجاوب**، مش كلها مرة واحدة في الآخر. كده لو قفل الصفحة أو النت قطع، اللي جاوبه محفوظ.

### `question_stats` (عرض للإحصائية)

```sql
create view question_stats with (security_invoker = true) as
select
  q.id,
  q.question,
  q.difficulty,
  count(*)                                              as times_answered,
  count(*) filter (where not aa.is_correct)             as times_wrong,
  round(100.0 * count(*) filter (where not aa.is_correct) / count(*)) as wrong_pct
from attempt_answers aa
join questions q on q.id = aa.question_id
group by q.id, q.question, q.difficulty;
```

صفحة الأدمن بتقرا منه مرتبة بـ `wrong_pct` تنازلياً، وبتتجاهل الأسئلة اللي اتجاوبت أقل من ٥ مرات (نسبة مبنية على إجابة أو اتنين مالهاش معنى).

## ٦. الصلاحيات (Row Level Security)

الفكرة الأساسية اللي بتبسّط كل حاجة: **الطالب بيدخل من غير تسجيل دخول خالص (`anon`)، وجورج هو الوحيد اللي بيسجل دخول (`authenticated`).** يعني "أدمن" = "مسجّل دخول"، من غير ما نحتاج جدول أدوار ولا أعمدة صلاحيات.

```sql
alter table questions       enable row level security;
alter table attempts        enable row level security;
alter table attempt_answers enable row level security;

-- الأسئلة: أي حد يقرا النشط منها فقط
create policy read_active_questions on questions
  for select to anon, authenticated using (active);

-- الأسئلة: الأدمن يعمل أي حاجة (بما فيها قراءة المخفي)
create policy admin_manages_questions on questions
  for all to authenticated using (true) with check (true);

-- المحاولات: أي حد يسجل محاولة، الأدمن بس يقراها
create policy anyone_inserts_attempt on attempts
  for insert to anon, authenticated with check (true);
create policy anyone_finishes_attempt on attempts
  for update to anon, authenticated using (finished_at is null) with check (true);
create policy admin_reads_attempts on attempts
  for select to authenticated using (true);

-- الإجابات: نفس الكلام
create policy anyone_inserts_answer on attempt_answers
  for insert to anon, authenticated with check (true);
create policy admin_reads_answers on attempt_answers
  for select to authenticated using (true);
```

النتيجة العملية: **طالب مش قادر يقرا نتيجة حد تاني ولا حتى نتيجته هو بعد ما يقفل الصفحة.** شاشة النتيجة بتتحسب في متصفحه من اللي لسه جاوبه، فمش محتاج يقرا من الداتابيز أصلاً.

**تفصيلتين مهمتين ناتجتين عن إن الطالب ممنوع من القراءة:**

١. مش هيقدر يستقبل الـ `id` بتاع المحاولة بعد ما يضيفها. فالحل إن **المتصفح هو اللي بيولّد الـ `id`** بـ `crypto.randomUUID()` قبل الإضافة، ويستخدمه في الجدولين. علشان كده `attempts.id` نوعه `uuid` مش رقم متسلسل — ده كمان بيخليه غير قابل للتخمين.

٢. الطالب محتاج يحدّث سطر محاولته في الآخر (`finished_at` و`score` و`total`)، فسياسة `anyone_finishes_attempt` بتسمح بالتحديث **للمحاولات اللي لسه ما خلصتش بس**. يعني مفيش حد يقدر يرجع يعدل في محاولة اتقفلت. عملياً محدش يقدر يعدل محاولة غيره أصلاً لأنه لازم يعرف الـ `uuid` بتاعها.

**حساب الأدمن** بيتعمل مرة واحدة بالإيد من لوحة تحكم Supabase (إيميل + باسورد)، وتسجيل الذاتي بيتقفل من إعدادات المشروع عشان محدش يعمل حساب لنفسه.

## ٧. الشاشات

### شاشة البداية (تعديل)

بتضاف خانة الاسم قبل زرار "ابدأ":

```
┌─────────────────────────────┐
│        الكويز               │
│                             │
│  اسمك:  [_______________]   │
│                             │
│      [ ابدأ الكويز ]        │
└─────────────────────────────┘
```

- الاسم مطلوب. زرار "ابدأ" مقفول لحد ما يتكتب اسم.
- الاسم بيتحفظ في `localStorage` عشان ميكتبوش تاني لو حل مرة تانية من نفس الجهاز.
- التنبيه الحالي (١٥ دقيقة ومفيش رجوع) بيفضل زي ما هو.

### الامتحان (نفس الشكل، السلوك الداخلي بس اللي اتغير)

- الأسئلة بتتجاب من الداتابيز بدل `questions.js` — نفس الـ `QUOTAS` ونفس العشوائية.
- سطر في `attempts` بيتكتب أول ما يدوس "ابدأ".
- سطر في `attempt_answers` بيتكتب مع كل إجابة.
- آخر سؤال بيحدّث `finished_at` و`score` و`total`.
- شاشة النتيجة والمراجعة بتفضل زي ما هي بالظبط.

### `pages/admin.html` (جديد)

**تسجيل الدخول** — إيميل وباسورد. بعد الدخول أربع تبويبات:

**أ. إضافة سؤال**

```
┌──────────────────────────────────────────────┐
│  إضافة سؤال جديد                             │
│                                              │
│  النوع:  ( ) اختيار  ( ) صح وغلط  ( ) أكمل   │
│                                              │
│  نص السؤال:                                  │
│  [__________________________________]        │
│   حط الحرف القبطي بين {{ }} — مثال:          │
│   الحرف {{ⲑ}} ينطق إزاي؟                     │
│   لو الرمز مش باين صح استخدم (( )) بدلها     │
│                                              │
│  الصعوبة: ( ) سهل  ( ) متوسط  ( ) صعب        │
│                                              │
│                      [ حفظ السؤال ]          │
└──────────────────────────────────────────────┘
```

الشرح اللي كان مكتوب كومنتات فوق `js/questions.js` بينتقل يبقى كلام ظاهر تحت الخانات في الشاشة دي — فبيبقى قدام العين وقت الكتابة بدل ما يكون في ملف كود.

الخانات بتتغير حسب النوع: `mcq` بيطلع خانات الاختيارات مع تحديد الصح، `truefalse` بيطلع اختيار صح/غلط، `fill` بيطلع خانة نص واحدة.

تحت الفورم **معاينة مباشرة** للسؤال بشكله النهائي بالخط القبطي، عشان يتأكد إن الحروف طالعة صح قبل الحفظ.

**ب. كل الأسئلة** — جدول بكل الأسئلة، فلترة بالنوع والصعوبة، بحث في النص، وزراير تعديل وإخفاء/إظهار.

**ج. المحاولات**

```
┌────────────────────────────────────────────────┐
│  المحاولات                        [بحث بالاسم] │
├────────────────────────────────────────────────┤
│  مينا      ١٦ سبتمبر ٨:٣٠ م      ٣٢ / ٤٠   ‹  │
│  مريم      ١٦ سبتمبر ٧:١٥ م      ٣٨ / ٤٠   ‹  │
│  مينا      ١٥ سبتمبر ٩:٠٠ م      ٢٥ / ٤٠   ‹  │
│  كيرلس     ١٥ سبتمبر ٦:٤٠ م      ٣٠ / ٤٠   ‹  │
└────────────────────────────────────────────────┘
```

مرتبة بالأحدث. المحاولات اللي ما خلصتش بتظهر معلّمة "ما خلصش". الضغط على سطر بيفتح تفاصيله:

```
┌────────────────────────────────────────────────┐
│  مينا — ١٦ سبتمبر ٨:٣٠ م — ٣٢ / ٤٠             │
├────────────────────────────────────────────────┤
│  ✅ ١. الأبجدية القبطية تتكون من كام حرف؟      │
│       إجابته: 32                               │
│                                                │
│  ❌ ٢. الحرف {{ⲑ}} ينطق إزاي؟                  │
│       إجابته: ت        الصح: ث                 │
└────────────────────────────────────────────────┘
```

بترتيب `position`، يعني بنفس ترتيب الامتحان اللي شافه الطالب.

**د. أصعب الأسئلة**

```
┌────────────────────────────────────────────────┐
│  أصعب الأسئلة على الناس                        │
├────────────────────────────────────────────────┤
│  الحرف {{ⲑ}} ينطق إزاي؟        غلط ٨٥٪ (١٧/٢٠)│
│  يعني ايه كلمة سمكة؟           غلط ٦٠٪ (١٢/٢٠)│
└────────────────────────────────────────────────┘
```

من `question_stats`، مرتبة بنسبة الغلط تنازلياً، والأسئلة اللي اتجاوبت أقل من ٥ مرات متستبعدة.

| الملف | متى |

## ٩. خطة النقل

1. عمل مشروع Supabase وإنشاء الجداول والصلاحيات.
2. عمل حساب الأدمن بالإيد وقفل التسجيل الذاتي.
3. `dev/migrate-questions.html`: صفحة بتحمّل `js/questions.js` كما هو، وبعد تسجيل دخول الأدمن بتضغط زرار واحد فتدفع الـ ١٠٠ سؤال للداتابيز بنفس الـ `id` ونفس الصعوبة.
4. **التحقق:** العدد ١٠٠، والتوزيع ١٦/٣٨/٤٦، وعينة أسئلة فيها حروف قبطية و`{{ }}` و`(( ))` بتتعرض صح.
5. بعد التحقق فقط: حذف `js/questions.js` و`dev/migrate-questions.html`.

النقل بصفحة HTML مش سكريبت Node عشان المشروع يفضل من غير `npm` ولا أي أدوات بناء.

## ١٠. برا النطاق

الحاجات دي **مش** هتتعمل، وموثقة هنا عشان تبقى قرارات واضحة مش نسيان:

- حسابات للطلبة، أو باسوردات، أو تسجيل دخول لأي حد غير الأدمن.
- أكتر من أدمن، أو أدوار وصلاحيات مختلفة.
- نظام موافقة على أسئلة بيضيفها ناس تانية.
- تصحيح الإجابات على السيرفر.
- تشغيل بدون إنترنت.
- تصدير النتايج لإكسيل أو PDF.

## ١١. مخاطر معروفة ومقبولة

**الدرجة بيحسبها متصفح الطالب.** حد فاهم في البرمجة يقدر يبعت درجة مضروبة. منعها بيتطلب تصحيح على السيرفر، وده تعقيد مش في محله بما إن الهدف تعليمي والمحاولات مفتوحة أصلاً والطالب بيشوف الإجابات في الآخر برضه.

**الإجابات الصح تقدر تتقرا من المتصفح.** ده الوضع الحالي بالظبط (الإجابات في ملف JS)، ومش هيتغير. مقبول لنفس السبب.

**أي حد يقدر يضيف محاولات.** لأن التسجيل مفتوح من غير حساب، حد يقدر يبعت محاولات وهمية. غير مرجح في السياق ده، ولو حصل بيتحل بحذف السطور من لوحة تحكم Supabase.

**المشروع بيتوقف مؤقتاً بعد أسبوع سكون.** في الباقة المجانية، لو عدّى أسبوع كامل محدش فتح الموقع، Supabase بتوقف المشروع لحد ما تدوس زرار تشغيل من لوحة التحكم. **الداتا متضيعش.** لو الاستخدام منتظم مش هتحصل أصلاً.

**الموقع بقى محتاج إنترنت.** دلوقتي ممكن يتفتح من غير نت، بعد التغيير لأ.
